> 这部分知识库覆盖后端工程师从语言基础、操作系统和网络，到数据库、中间件、分布式架构、云原生与工程实践的主干知识。这个导航页的目标是把 19 篇文档串成清晰路线，方便按面试、补基础或专项提升来阅读。

## 先回答：后端知识库到底在学什么

后端不是只学某一门语言，也不是背一套框架 API。建议先把知识拆成 6 层：

- `系统基础`：操作系统、网络协议、并发模型，决定你能否解释服务为什么会慢、为什么会挂
- `编程语言`：Go、Java、Python、C++，决定你能否写出可靠、高性能、可维护的服务
- `数据存储`：MySQL、Redis、PostgreSQL、ClickHouse、MongoDB、Elasticsearch，决定你能否设计数据模型和查询路径
- `中间件`：消息队列、缓存、搜索、配置、网关，决定你能否把单体能力拆成可扩展系统
- `架构设计`：限流、熔断、分布式事务、一致性、微服务、云原生，决定你能否处理规模、可用性和演进问题
- `工程治理`：API 设计、认证授权、设计模式、可观测性、部署与运维，决定系统能否长期稳定迭代

面试时不要把这些层孤立背诵。更好的方式是从一个业务场景出发，能说清楚请求如何进入系统、数据如何落库、失败如何恢复、服务如何扩容。

## 一周面试复盘节奏

1. 第 1 天：操作系统 + 网络，复盘服务运行、IO、TCP/HTTP、排障链路。
2. 第 2 天：MySQL + Redis，复盘索引、事务、锁、缓存一致性和热点问题。
3. 第 3 天：消息队列 + Elasticsearch，复盘异步解耦、可靠性、搜索索引和集群问题。
4. 第 4 天：主语言，按目标岗位复盘 Go / Java / Python / C++。
5. 第 5 天：系统设计与微服务，练习限流、熔断、分布式事务、高可用。
6. 第 6 天：API、认证授权、设计模式，补工程治理和安全边界。
7. 第 7 天：英文版复述高频问题，重点练系统设计表达和 trade-off。

## 阅读时最容易踩的坑

- 只背概念，不知道它解决什么生产问题。比如 MQ 不只是异步工具，还带来幂等、重试、DLQ、积压治理。
- 把系统设计当模板背。面试官更关注约束、容量估算、失败路径和取舍。
- 只讲“怎么做”，不讲“为什么不选其他方案”。中高级面试里 trade-off 比方案名更重要。
- 忽略可观测性。没有指标、日志、追踪、告警的架构很难在生产环境长期运行。
- 英文面试逐字翻译中文答案。更好的表达是：`In short...` → `The reason is...` → `In production, I would...`。
