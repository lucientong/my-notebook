## 1. 数组与哈希表

### 1.1 数组底层原理

#### 为什么数组查找是O(1)？

**内存布局**：
```
数组: [10, 20, 30, 40, 50]
内存地址：
  arr[0] → 0x1000  (存储10)
  arr[1] → 0x1004  (存储20，假设int占4字节)
  arr[2] → 0x1008  (存储30)
  arr[3] → 0x100C  (存储40)
  arr[4] → 0x1010  (存储50)
```

**访问arr[i]的计算**：
```
地址 = base_address + i * element_size
     = 0x1000 + 2 * 4
     = 0x1008  (arr[2])
```

**为什么是O(1)？**
- 数组在内存中连续存储
- 通过简单的**数学计算**直接得到地址
- 不需要遍历，只需要一次内存访问

---

#### 数组 vs 链表

| 特性 | 数组 | 链表 |
|------|------|------|
| **随机访问** | O(1) - 通过索引直接计算地址 | O(n) - 需要从头遍历 |
| **插入/删除（头部）** | O(n) - 需要移动后续元素 | O(1) - 只需修改指针 |
| **插入/删除（末尾）** | O(1)* - 直接添加 | O(n) - 需要遍历到末尾 |
| **内存** | 连续 - 缓存友好 | 分散 - 缓存不友好 |
| **空间利用** | 可能浪费（预分配） | 每个节点需要额外指针 |

**工程中如何选择？**
- **数组**：需要频繁随机访问（如排序、二分查找）
- **链表**：频繁插入/删除，且主要在头部操作（如LRU缓存）

### 1.2 动态数组实现

#### 为什么需要动态数组？

静态数组大小固定，动态数组可以自动扩容。

#### 手写动态数组

```python
class ArrayList:
    """
    动态数组实现
    
    扩容策略：容量不足时，扩容到2倍
    """
    def __init__(self):
        self.capacity = 10  # 初始容量
        self.size = 0       # 当前元素个数
        self.data = [None] * self.capacity
    
    def append(self, value):
        """
        添加元素
        时间复杂度：均摊O(1)
        """
        # 容量不足，扩容
        if self.size == self.capacity:
            self._resize(self.capacity * 2)
        
        self.data[self.size] = value
        self.size += 1
    
    def _resize(self, new_capacity):
        """
        扩容：创建新数组，复制旧数据
        时间复杂度：O(n)
        """
        new_data = [None] * new_capacity
        for i in range(self.size):
            new_data[i] = self.data[i]
        self.data = new_data
        self.capacity = new_capacity
    
    def get(self, index):
        """访问元素：O(1)"""
        if index < 0 or index >= self.size:
            raise IndexError("Index out of range")
        return self.data[index]
    
    def insert(self, index, value):
        """
        插入元素：O(n)
        需要移动index后的所有元素
        """
        if self.size == self.capacity:
            self._resize(self.capacity * 2)
        
        # 从后往前移动元素
        for i in range(self.size, index, -1):
            self.data[i] = self.data[i - 1]
        
        self.data[index] = value
        self.size += 1
    
    def remove(self, index):
        """
        删除元素：O(n)
        需要移动index后的所有元素
        """
        if index < 0 or index >= self.size:
            raise IndexError("Index out of range")
        
        # 向前移动元素
        for i in range(index, self.size - 1):
            self.data[i] = self.data[i + 1]
        
        self.size -= 1
        self.data[self.size] = None  # 清理引用
        
        # 缩容：元素个数小于容量1/4时，缩容到1/2
        if self.size < self.capacity // 4 and self.capacity > 10:
            self._resize(self.capacity // 2)
```

#### 为什么append是"均摊O(1)"？

**扩容分析**：
```
初始容量：10
添加第1-10个元素：无需扩容，10次O(1)
添加第11个元素：扩容到20，复制10个元素，O(10)
添加第12-20个元素：无需扩容，9次O(1)
添加第21个元素：扩容到40，复制20个元素，O(20)
...

总成本：n + (10 + 20 + 40 + ...) ≈ n + 2n = 3n
均摊成本：3n / n = O(1)
```

**为什么扩容到2倍？**
- 如果扩容到n+1：每次添加都需要扩容，O(n²)
- 如果扩容到1.5倍或2倍：均摊O(1)
- Python/Java使用2倍，Go使用1.25倍（Go针对大数组优化）

### 1.3 哈希表底层原理

#### 为什么哈希表查找是O(1)？

**核心思想**：通过哈希函数将key映射到数组索引

```
key → hash(key) → index → value

例如：
"apple" → hash("apple") = 123456 → 123456 % 10 = 6 → bucket[6]
```

#### 哈希函数设计

**好的哈希函数特点**：
1. **确定性**：相同key必须产生相同hash
2. **均匀分布**：不同key应尽量映射到不同位置
3. **快速计算**：O(1)时间

**常见哈希函数**：

```python
def hash_string(s, table_size):
    """
    字符串哈希（多项式滚动哈希）
    """
    hash_value = 0
    p = 31  # 质数
    power = 1
    
    for char in s:
        hash_value = (hash_value + ord(char) * power) % table_size
        power = (power * p) % table_size
    
    return hash_value

def hash_int(key, table_size):
    """整数哈希（除留余数法）"""
    return key % table_size
```

---

#### 哈希冲突解决

**问题**：不同key可能映射到同一个索引

**解决方案1：链地址法（Chaining）**

```python
class HashMapChaining:
    """
    链地址法：每个bucket存储一个链表
    
    时间复杂度：
    - 最好：O(1) - 无冲突
    - 平均：O(1 + α) - α为负载因子（n/m）
    - 最坏：O(n) - 所有key映射到同一个bucket
    """
    def __init__(self, capacity=16):
        self.capacity = capacity
        self.size = 0
        self.buckets = [[] for _ in range(capacity)]
    
    def _hash(self, key):
        """哈希函数"""
        return hash(key) % self.capacity
    
    def put(self, key, value):
        """插入/更新"""
        index = self._hash(key)
        bucket = self.buckets[index]
        
        # 查找是否已存在
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)  # 更新
                return
        
        # 不存在，添加
        bucket.append((key, value))
        self.size += 1
        
        # 负载因子过高，扩容
        if self.size / self.capacity > 0.75:
            self._resize()
    
    def get(self, key):
        """查找"""
        index = self._hash(key)
        bucket = self.buckets[index]
        
        for k, v in bucket:
            if k == key:
                return v
        
        raise KeyError(key)
    
    def remove(self, key):
        """删除"""
        index = self._hash(key)
        bucket = self.buckets[index]
        
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket.pop(i)
                self.size -= 1
                return
        
        raise KeyError(key)
    
    def _resize(self):
        """扩容：重新哈希所有元素"""
        old_buckets = self.buckets
        self.capacity *= 2
        self.buckets = [[] for _ in range(self.capacity)]
        self.size = 0
        
        for bucket in old_buckets:
            for key, value in bucket:
                self.put(key, value)
```

**链地址法优缺点**：
- ✅ 实现简单
- ✅ 删除方便
- ❌ 需要额外指针空间
- ❌ 缓存不友好（链表节点分散）

**解决方案2：开放寻址法（Open Addressing）**

```python
class HashMapOpenAddressing:
    """
    开放寻址法：线性探测
    
    冲突时，向后查找下一个空位：
    index, index+1, index+2, ...
    """
    def __init__(self, capacity=16):
        self.capacity = capacity
        self.size = 0
        self.keys = [None] * capacity
        self.values = [None] * capacity
        self.DELETED = object()  # 删除标记
    
    def _hash(self, key):
        return hash(key) % self.capacity
    
    def put(self, key, value):
        """插入/更新"""
        if self.size / self.capacity > 0.5:  # 负载因子阈值
            self._resize()
        
        index = self._hash(key)
        
        # 线性探测
        while self.keys[index] is not None:
            if self.keys[index] == key:
                self.values[index] = value  # 更新
                return
            
            if self.keys[index] == self.DELETED:
                break  # 可以复用删除位置
            
            index = (index + 1) % self.capacity  # 环形查找
        
        self.keys[index] = key
        self.values[index] = value
        self.size += 1
    
    def get(self, key):
        """查找"""
        index = self._hash(key)
        
        # 线性探测查找
        while self.keys[index] is not None:
            if self.keys[index] == key:
                return self.values[index]
            index = (index + 1) % self.capacity
        
        raise KeyError(key)
    
    def remove(self, key):
        """删除：标记为DELETED，不能直接置None"""
        index = self._hash(key)
        
        while self.keys[index] is not None:
            if self.keys[index] == key:
                self.keys[index] = self.DELETED
                self.values[index] = None
                self.size -= 1
                return
            index = (index + 1) % self.capacity
        
        raise KeyError(key)
```

**为什么删除要用标记而不是直接置None？**

```
假设：hash("a") = hash("b") = 0
插入顺序：a → bucket[0], b → bucket[1]（冲突后探测）

如果删除a时直接置None：
bucket[0] = None
查找b时：hash("b")=0，bucket[0]=None，误认为b不存在！

正确做法：
bucket[0] = DELETED
查找b时：遇到DELETED继续探测，找到bucket[1]
```

**开放寻址法优缺点**：
- ✅ 缓存友好（连续内存）
- ✅ 节省指针空间
- ❌ 删除复杂（需要标记）
- ❌ 负载因子不能太高（否则探测链很长）

---

#### 负载因子与性能

**负载因子** α = n / m（n为元素个数，m为bucket数）

| 负载因子 | 链地址法平均查找次数 | 开放寻址法平均查找次数 |
|----------|---------------------|----------------------|
| 0.5 | 1.25 | 1.5 |
| 0.75 | 1.5 | 3.0 |
| 1.0 | 2.0 | ∞（理论上） |

**工程中的选择**：
- **Java HashMap**：链地址法，α=0.75时扩容，链表长度>8转红黑树
- **Python dict**：开放寻址法，α=2/3时扩容
- **Redis dict**：链地址法，渐进式rehash避免阻塞

### 1.4 哈希表工程应用

#### 应用1：数据库索引（为什么不用哈希表？）

**哈希表的问题**：
1. **不支持范围查询**：`SELECT * WHERE age BETWEEN 20 AND 30`

**哈希索引的使用场景**：
- 等值查询：`WHERE id = 123`
- Memory引擎
- 自适应哈希索引（InnoDB）

#### 应用2：Redis的dict

**为什么Redis用渐进式rehash？**

```python
# 普通rehash：一次性重新哈希所有key，可能阻塞很久
def rehash_blocking(old_dict):
    new_dict = create_new_dict(old_dict.size * 2)
    for key, value in old_dict:  # ⚠️ 可能有100万个key
        new_dict.put(key, value)
    return new_dict  # 阻塞时间：O(n)

# 渐进式rehash：每次操作时迁移少量key
class RedisDict:
    def __init__(self):
        self.ht = [HashTable(), HashTable()]  # 两个哈希表
        self.rehashidx = -1  # -1表示未在rehash
    
    def put(self, key, value):
        # 正在rehash，先迁移一个bucket
        if self.rehashidx != -1:
            self._rehash_step()
        
        # 正常插入
        index = 0 if self.rehashidx == -1 else 1
        self.ht[index].put(key, value)
        
        # 触发rehash
        if self.should_resize():
            self._start_rehash()
    
    def _rehash_step(self):
        """迁移一个bucket"""
        bucket = self.ht[0].buckets[self.rehashidx]
        for key, value in bucket:
            self.ht[1].put(key, value)
        
        self.ht[0].buckets[self.rehashidx] = []
        self.rehashidx += 1
        
        # 迁移完成
        if self.rehashidx >= len(self.ht[0].buckets):
            self.ht[0] = self.ht[1]
            self.ht[1] = HashTable()
            self.rehashidx = -1
```

**优点**：
- 每次操作只迁移少量数据
- 避免长时间阻塞
- 适合单线程模型

#### 应用3：一致性哈希（分布式缓存）

**问题**：普通哈希在节点变化时，大量key需要迁移

```python
# 普通哈希：节点变化时，几乎所有key都要迁移
node_index = hash(key) % num_nodes

# 3个节点时："user123" → hash % 3 = 1 → node1
# 4个节点时："user123" → hash % 4 = 3 → node3  ⚠️ 迁移！
```

**一致性哈希**：

```python
class ConsistentHash:
    """
    一致性哈希：节点变化时，只有相邻节点的key需要迁移
    """
    def __init__(self, nodes, virtual_nodes=150):
        self.ring = {}  # 哈希环
        self.sorted_keys = []
        self.virtual_nodes = virtual_nodes
        
        for node in nodes:
            self.add_node(node)
    
    def add_node(self, node):
        """添加节点：创建virtual_nodes个虚拟节点"""
        for i in range(self.virtual_nodes):
            virtual_key = f"{node}#{i}"
            hash_value = hash(virtual_key)
            self.ring[hash_value] = node
            self.sorted_keys.append(hash_value)
        
        self.sorted_keys.sort()
    
    def get_node(self, key):
        """查找key应该存储在哪个节点"""
        if not self.ring:
            return None
        
        hash_value = hash(key)
        
        # 二分查找：找第一个>=hash_value的节点
        idx = bisect.bisect_right(self.sorted_keys, hash_value)
        if idx == len(self.sorted_keys):
            idx = 0  # 环形
        
        return self.ring[self.sorted_keys[idx]]
```

**为什么需要虚拟节点？**
- 物理节点少时，分布不均匀
- 虚拟节点让key分布更均匀

## 2. 链表

### 2.1 链表底层原理

#### 为什么链表插入是O(1)？

**数组插入**：
```
数组: [1, 2, 3, 4, 5]
插入6到索引2：
1. 移动元素：[1, 2, _, 3, 4, 5] ← 需要移动3个元素
2. 插入：[1, 2, 6, 3, 4, 5]
时间复杂度：O(n)
```

**链表插入**：
```
链表: 1 → 2 → 3 → 4 → 5
插入6到节点2后：
1. new_node.next = node2.next  // 6 → 3
2. node2.next = new_node        // 2 → 6
时间复杂度：O(1)（假设已经找到node2）
```

**为什么？**
- 链表节点在内存中不连续
- 插入只需修改指针，不需要移动元素

### 2.2 手写链表

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class LinkedList:
    """单向链表"""
    def __init__(self):
        self.head = None
        self.size = 0
    
    def add_first(self, val):
        """头部插入：O(1)"""
        new_node = ListNode(val, self.head)
        self.head = new_node
        self.size += 1
    
    def add_last(self, val):
        """尾部插入：O(n)"""
        if not self.head:
            self.head = ListNode(val)
        else:
            curr = self.head
            while curr.next:  # 遍历到末尾
                curr = curr.next
            curr.next = ListNode(val)
        self.size += 1
    
    def remove_first(self):
        """头部删除：O(1)"""
        if not self.head:
            raise Exception("List is empty")
        self.head = self.head.next
        self.size -= 1
    
    def get(self, index):
        """访问元素：O(n)"""
        if index < 0 or index >= self.size:
            raise IndexError()
        
        curr = self.head
        for _ in range(index):
            curr = curr.next
        return curr.val
```

#### 为什么需要哨兵节点（Dummy Node）？

**问题**：处理头节点时需要特殊判断

```python
# 没有哨兵节点：需要判断head
def remove_value(head, val):
    # 特殊处理头节点
    while head and head.val == val:
        head = head.next
    
    # 处理其他节点
    curr = head
    while curr and curr.next:
        if curr.next.val == val:
            curr.next = curr.next.next
        else:
            curr = curr.next
    return head

# 有哨兵节点：统一处理
def remove_value(head, val):
    dummy = ListNode(0, head)  # 哨兵节点
    curr = dummy
    
    while curr.next:
        if curr.next.val == val:
            curr.next = curr.next.next
        else:
            curr = curr.next
    
    return dummy.next  # 返回真正的头节点
```

### 2.3 双向链表

```python
class DListNode:
    def __init__(self, val=0, prev=None, next=None):
        self.val = val
        self.prev = prev
        self.next = next

class DoublyLinkedList:
    """
    双向链表：支持O(1)尾部操作
    
    使用哨兵节点简化边界处理
    """
    def __init__(self):
        self.head = DListNode()  # 哨兵头
        self.tail = DListNode()  # 哨兵尾
        self.head.next = self.tail
        self.tail.prev = self.head
        self.size = 0
    
    def add_first(self, val):
        """头部插入：O(1)"""
        self._insert_after(self.head, val)
    
    def add_last(self, val):
        """尾部插入：O(1)"""
        self._insert_before(self.tail, val)
    
    def _insert_after(self, node, val):
        """在node后插入"""
        new_node = DListNode(val, node, node.next)
        node.next.prev = new_node
        node.next = new_node
        self.size += 1
    
    def _insert_before(self, node, val):
        """在node前插入"""
        new_node = DListNode(val, node.prev, node)
        node.prev.next = new_node
        node.prev = new_node
        self.size += 1
    
    def remove_first(self):
        """删除头节点：O(1)"""
        if self.size == 0:
            raise Exception("List is empty")
        self._remove_node(self.head.next)
    
    def remove_last(self):
        """删除尾节点：O(1)"""
        if self.size == 0:
            raise Exception("List is empty")
        self._remove_node(self.tail.prev)
    
    def _remove_node(self, node):
        """删除指定节点：O(1)"""
        node.prev.next = node.next
        node.next.prev = node.prev
        self.size -= 1
```

### 2.4 链表工程应用

#### 应用1：LRU缓存（哈希表+双向链表）

**为什么需要双向链表？**
- 需要O(1)删除任意节点
- 单向链表删除节点需要O(n)找到前驱节点

```python
class LRUCache:
    """
    LRU缓存：
    - 哈希表：O(1)查找节点
    - 双向链表：O(1)移动节点到头部/删除尾部
    
    结构：
    HashMap: key → Node
    DoublyLinkedList: head ↔ node1 ↔ node2 ↔ ... ↔ tail
    （最近使用的在head，最久未使用的在tail）
    """
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}  # key → Node
        self.head = DListNode()  # 哨兵头（最近使用）
        self.tail = DListNode()  # 哨兵尾（最久未使用）
        self.head.next = self.tail
        self.tail.prev = self.head
    
    def get(self, key: int) -> int:
        """
        获取值：O(1)
        1. 哈希表查找节点
        2. 移动到头部（标记为最近使用）
        """
        if key not in self.cache:
            return -1
        
        node = self.cache[key]
        self._move_to_head(node)
        return node.val
    
    def put(self, key: int, value: int) -> None:
        """
        插入/更新：O(1)
        """
        if key in self.cache:
            # 已存在，更新并移到头部
            node = self.cache[key]
            node.val = value
            self._move_to_head(node)
        else:
            # 不存在，插入
            if len(self.cache) >= self.capacity:
                # 容量已满，删除尾部（LRU）
                removed = self._remove_tail()
                del self.cache[removed.key]
            
            # 创建新节点，插入头部
            new_node = DListNode(key, value)
            self.cache[key] = new_node
            self._add_to_head(new_node)
    
    def _move_to_head(self, node):
        """移动节点到头部"""
        self._remove_node(node)
        self._add_to_head(node)
    
    def _remove_node(self, node):
        """删除节点：O(1)"""
        node.prev.next = node.next
        node.next.prev = node.prev
    
    def _add_to_head(self, node):
        """添加到头部：O(1)"""
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node
    
    def _remove_tail(self):
        """删除尾部节点：O(1)"""
        node = self.tail.prev
        self._remove_node(node)
        return node
```

**时间复杂度分析**：
- `get(key)`: O(1) - 哈希表查找 + 链表移动
- `put(key, value)`: O(1) - 哈希表插入 + 链表操作

**如果只用链表（不用哈希表）**：
- `get(key)`: O(n) - 需要遍历链表查找
- **哈希表的作用：将查找从O(n)优化到O(1)**

#### 应用2：跳表（SkipList）

**为什么需要跳表？**
- 有序链表查找：O(n)
- 跳表查找：O(logn)
- Redis的有序集合（Sorted Set）底层使用跳表

**原理**：多层链表，每层间隔递增

```
Level 2:  1 ---------------→ 7
Level 1:  1 ------→ 4 ------→ 7
Level 0:  1 → 2 → 3 → 4 → 5 → 6 → 7

查找6：
1. 从Level 2开始：1 → 7（跳过）
2. 下降到Level 1：1 → 4 → 7（4<6<7）
3. 下降到Level 0：4 → 5 → 6（找到）
```

**为什么Redis用跳表而不是红黑树？**
1. **实现简单**：跳表比红黑树容易实现
2. **范围查询友好**：底层是链表，范围遍历方便
3. **性能相当**：都是O(logn)
4. **内存占用**：跳表略高，但可接受

### 3.1 栈底层原理

#### 为什么栈是LIFO（后进先出）？

**内存模型**：
```
栈顶 →  |  30  |  ← push(30)最后进
        |  20  |  ← push(20)
        |  10  |  ← push(10)最先进
栈底
```

**操作**：
- `push(x)`: 栈顶指针+1，存储x
- `pop()`: 返回栈顶元素，栈顶指针-1

**为什么push/pop是O(1)？**
- 只操作栈顶，不涉及其他元素

### 3.2 手写栈

```python
class ArrayStack:
    """
    数组实现栈
    """
    def __init__(self, capacity=10):
        self.data = [None] * capacity
        self.top = -1  # 栈顶指针
        self.capacity = capacity
    
    def push(self, val):
        """入栈：O(1)"""
        if self.top + 1 >= self.capacity:
            raise Exception("Stack overflow")
        self.top += 1
        self.data[self.top] = val
    
    def pop(self):
        """出栈：O(1)"""
        if self.is_empty():
            raise Exception("Stack underflow")
        val = self.data[self.top]
        self.top -= 1
        return val
    
    def peek(self):
        """查看栈顶：O(1)"""
        if self.is_empty():
            raise Exception("Stack is empty")
        return self.data[self.top]
    
    def is_empty(self):
        return self.top == -1
```

#### 应用2：表达式求值

```python
def evaluate_postfix(expression):
    """
    后缀表达式求值
    
    例如："3 4 + 2 *" = (3 + 4) * 2 = 14
    
    算法：
    1. 遇到数字，入栈
    2. 遇到运算符，弹出2个数字计算，结果入栈
    """
    stack = []
    
    for token in expression.split():
        if token.isdigit():
            stack.append(int(token))
        else:
            b = stack.pop()
            a = stack.pop()
            
            if token == '+':
                stack.append(a + b)
            elif token == '-':
                stack.append(a - b)
            elif token == '*':
                stack.append(a * b)
            elif token == '/':
                stack.append(a // b)
    
    return stack[0]
```

#### 应用3：单调栈

**问题**：下一个更大元素

```python
def next_greater_element(nums):
    """
    输入：[2, 1, 2, 4, 3]
    输出：[4, 2, 4, -1, -1]
    
    解释：
    - nums[0]=2，下一个更大的是nums[3]=4
    - nums[1]=1，下一个更大的是nums[2]=2
    
    时间复杂度：O(n)
    """
    n = len(nums)
    result = [-1] * n
    stack = []  # 单调递减栈（存储索引）
    
    for i in range(n):
        # 当前元素大于栈顶，说明找到了栈顶元素的下一个更大元素
        while stack and nums[i] > nums[stack[-1]]:
            index = stack.pop()
            result[index] = nums[i]
        
        stack.append(i)
    
    return result
```

**为什么是O(n)？**
- 每个元素最多入栈出栈各1次
- 总操作次数：2n = O(n)

### 3.4 队列底层原理

#### 循环队列实现

**问题**：普通数组实现队列，出队后前面空间浪费

```python
class CircularQueue:
    """
    循环队列：充分利用数组空间
    
    关键：
    - front: 队首指针
    - rear: 队尾指针
    - (rear + 1) % capacity = front 时队列满
    """
    def __init__(self, capacity):
        self.data = [None] * (capacity + 1)  # 多1个空间区分空/满
        self.front = 0
        self.rear = 0
        self.capacity = capacity + 1
    
    def enqueue(self, val):
        """入队：O(1)"""
        if self.is_full():
            raise Exception("Queue is full")
        self.data[self.rear] = val
        self.rear = (self.rear + 1) % self.capacity  # 循环
    
    def dequeue(self):
        """出队：O(1)"""
        if self.is_empty():
            raise Exception("Queue is empty")
        val = self.data[self.front]
        self.front = (self.front + 1) % self.capacity
        return val
    
    def is_empty(self):
        return self.front == self.rear
    
    def is_full(self):
        return (self.rear + 1) % self.capacity == self.front
```

**为什么需要多1个空间？**

```
不多1个空间：
- 空队列：front = rear = 0
- 满队列：front = rear = 0  ⚠️ 无法区分空/满！

多1个空间：
- 空：front = rear
- 满：(rear + 1) % capacity = front  ✅ 可以区分
```

## 4. 树

### 4.0 二叉树 DFS：前/中/后序如何区分 ⭐⭐⭐

> **刷题对照**：[03-LeetCode分类刷题指南 §5.2](./03-LeetCode分类刷题指南.md#52-前中后序如何区分与选型)

#### 先记定义：看谁在最后被「处理」

前/中/后序说的是 **对当前节点做主要业务处理** 的时机，相对左右递归的顺序：

| 遍历 | 顺序 | 典型代码结构 |
|------|------|--------------|
| **前序** | 根 → 左 → 右 | 处理 root → `dfs(left)` → `dfs(right)` |
| **中序** | 左 → 根 → 右 | `dfs(left)` → 处理 root → `dfs(right)` |
| **后序** | 左 → 右 → 根 | `dfs(left)` → `dfs(right)` → 处理 root |

这里的 **「处理 root」** 指：用 `root` 的值做本题核心逻辑（收集结果、计算返回值、更新答案等），**不是** 函数开头的 `if root == nil { return }`。

#### 常见误区：开头判空 ≠ 前序

```go
func dfs(root *TreeNode) int {
    if root == nil {        // ← 递归终止条件，三种遍历都可以写在这里
        return 0
    }
    left := dfs(root.Left)  // 先左
    right := dfs(root.Right) // 再右
    return f(left, right) + 1  // ← 「处理 root」在这里 → 后序
}
```

很多人看到 **先写 `if root == nil`** 就以为是前序——错。终止条件只是边界，**看谁依赖子树结果** 才能定序。

#### 如何判断一道题是哪种序？

```
当前节点的答案，是否依赖左右子树的返回值？
├─ 是 → 后序（自底向上汇总）
├─ 否，需要先访问 root 再往下 → 前序（自顶向下传递）
└─ 否，需要左子树有序后再处理 root → 中序（BST 中序得升序）
```

#### 三类典型题

**后序——「问孩子，再决定父亲」**

| 题目 | 为什么后序 |
|------|-----------|
| LC104 最大深度 | `max(left, right) + 1`，深度依赖子树 |
| LC236 LCA | 根据 left、right 是否非 nil 决定返回 root 还是向上传递 |
| LC124 最大路径和 | 子树贡献算完才能算经过 root 的路径 |
| LC543 直径 | 左右深度都知才能算经过 root 的路径 |

```python
# 后序模板（分解/DP on tree）
def dfs(root):
    if not root:
        return base
    left = dfs(root.left)
    right = dfs(root.right)
    # 用 left、right 处理 root
    return combine(left, right, root)
```

**前序——「先定 root，再往下传」**

| 题目 | 为什么前序 |
|------|-----------|
| LC297 序列化 | 先输出 root，再序列化左右 |
| LC257 二叉树路径 | 先把 root 加入路径，再递归子树 |
| LC114 展平二叉树 | 先处理 root 的指针，再递归 |

```python
# 前序模板（遍历/自顶向下传参）
def dfs(root, state):
    if not root:
        return
    process(root, state)      # 先处理 root
    dfs(root.left, state)
    dfs(root.right, state)
```

**中序——「左子树处理完，再处理 root」**

| 题目 | 为什么中序 |
|------|-----------|
| LC94 中序遍历 | 定义即中序 |
| LC98 验证 BST | 中序序列必须严格递增 |
| LC230 BST 第 K 小 | 中序第 K 个 |

```python
# 中序模板
def dfs(root):
    if not root:
        return
    dfs(root.left)
    process(root)             # 左子树完后再处理 root
    dfs(root.right)
```

#### LC236 LCA 为什么是后序？（手推）

```go
left := lca(root.Left, p, q)
right := lca(root.Right, p, q)
if left != nil && right != nil { return root }  // ← 处理 root 在左右之后
```

- `p == root || q == root` 的 return 是 **边界/信号**，不是前序意义上的「处理根」
- 真正决定 LCA 的是 **左右子树都汇报完之后** 的 `if left && right`

#### 前/中/后序在这题里能互换吗？

| 题型 | 能否换序 |
|------|----------|
| 依赖子树返回值（深度、LCA、路径和） | ❌ 必须后序 |
| 自顶向下传参（路径、序列化） | ❌ 必须前序 |
| BST 有序性 | ❌ 必须中序 |
| 纯收集所有节点值 | ✅ 三种都能遍历完，但输出顺序不同 |

**结论**：不是「三种都能做同一道题」，而是 **题目信息流向** 决定了必须用哪种序。

#### 与「遍历思维 vs 分解思维」的关系

| 思维 | 常见遍历序 | 返回值 |
|------|------------|--------|
| **遍历思维** | 前序为主 | void，用外部变量收集 |
| **分解思维** | 后序为主 | 函数返回子问题答案，父节点 combine |

### 4.3 红黑树（Java HashMap、Linux进程调度）

#### 红黑树性质

1. **节点是红色或黑色**
2. **根节点是黑色**
3. **叶子节点（NIL）是黑色**
4. **红色节点的子节点必须是黑色**（不能有连续的红节点）
5. **从根到叶子的所有路径，黑色节点数量相同**

**为什么这5条性质保证平衡？**

性质4+5推导：
```
最短路径：全是黑节点
最长路径：红黑交替

假设黑高度为h（根到叶子的黑节点数）：
- 最短路径长度：h
- 最长路径长度：2h（红黑交替）

最长路径 ≤ 2 * 最短路径
→ 近似平衡（不是严格平衡）
```

**红黑树 vs AVL树**：

| 特性 | 红黑树 | AVL树 |
|------|--------|-------|
| **平衡条件** | 最长路径≤2倍最短路径 | 左右高度差≤1 |
| **平衡程度** | 近似平衡 | 严格平衡 |
| **查找性能** | O(logn) | O(logn)，更快 |
| **插入/删除** | 更少旋转，更快 | 更多旋转 |
| **应用** | Java HashMap、Linux CFS | 数据库（要求严格平衡） |

---

#### 工程应用1：Java HashMap的树化

**为什么HashMap要树化？**

```java
// Java 8之前：链地址法
HashMap: bucket → 链表

// Java 8：链表长度>8时树化
HashMap: bucket → 红黑树

// 为什么？
哈希碰撞攻击：恶意构造大量相同hash的key
- 链表：O(n)查找，n很大时性能崩溃
- 红黑树：O(logn)查找，最坏情况有保障
```

**为什么是8？**
- 泊松分布：正常情况下，链表长度达到8的概率极低（0.00000006）
- 如果达到8，很可能是恶意攻击
- 树化有额外开销，不宜过早

**为什么<6时退化回链表？**
- 避免频繁树化/退化
- 6-8是缓冲区（Hysteresis）

#### 工程应用2：Linux CFS调度器

**完全公平调度器（CFS）**：用红黑树管理进程

```c
// Linux内核代码（简化）
struct cfs_rq {
    struct rb_root_cached tasks_timeline;  // 红黑树根
};

struct sched_entity {
    u64 vruntime;  // 虚拟运行时间（key）
    struct rb_node run_node;  // 红黑树节点
};
```

**为什么用红黑树？**
1. **按vruntime排序**：最左节点是最需要运行的进程
2. **O(logn)插入/删除**：进程频繁睡眠/唤醒
3. **O(1)获取最小值**：直接取最左节点

**调度过程**：
```
1. 取红黑树最左节点（vruntime最小的进程）
2. 运行该进程一段时间
3. 更新vruntime
4. 重新插入红黑树
```

**为什么不用堆？**
- 堆只支持取最小值，不支持范围查询
- 红黑树支持遍历所有进程（debug、统计）

---

### 4.4 B+树（MySQL索引）

#### 为什么MySQL用B+树？

**问题**：红黑树在磁盘上效率低

```
红黑树高度：log₂(n)
- 100万数据：log₂(10⁶) ≈ 20层
- 每层1次磁盘I/O：20次I/O！
```

**B+树高度**：log_m(n)，m为节点容量

```
B+树（m=1000）：log₁₀₀₀(10⁶) ≈ 2层
- 只需2-3次I/O！
```

#### B+树原理

**结构**：
```
非叶子节点：只存key，不存data（高扇出）
叶子节点：存key+data，且通过链表连接

         [10, 20, 30]  ← 非叶子节点（索引）
        /    |    |    \
      /      |    |      \
   [1,5,8] [10,15] [20,25] [30,35,40]  ← 叶子节点（数据+链表）
      ↔       ↔       ↔        ↔
```

**B+树 vs B树**：

| 特性 | B+树 | B树 |
|------|------|-----|
| **非叶子节点** | 只存key | 存key+data |
| **叶子节点** | 存所有data，有链表 | 部分data，无链表 |
| **范围查询** | O(logn + k) - 链表遍历 | O(klogn) - 每个都要查 |
| **磁盘I/O** | 更少（非叶子节点小） | 更多 |

**为什么适合磁盘？**
1. **高扇出**：每个节点存多个key，减少高度
2. **顺序I/O**：叶子节点链表，范围查询快
3. **预读**：一次读一个磁盘页（4KB），B+树节点正好一页

---

#### 工程细节：InnoDB的B+树

**每个节点16KB**：
```
非叶子节点：
- key（8B）+ 指针（6B）= 14B
- 16KB / 14B ≈ 1170个key
- 扇出：1170

三层B+树可存储：
1170 × 1170 × 16 ≈ 2000万条记录
只需3次I/O！
```

**为什么主键建议用自增ID？**
```
自增ID：顺序插入，B+树只分裂最右节点
UUID：随机插入，频繁分裂中间节点，产生碎片
```

## 5. 堆


---

### 5.1 堆是什么

**堆（Heap）** 是一种基于 **完全二叉树** 的数据结构，满足特定的 **堆序性质**，用于 **高效获取最值**（最小或最大）。

```
        1          ← 堆顶（root）：小根堆里全局最小
      /   \
     3     2        ← 每个节点 ≤ 其孩子（小根堆）
    / \   /
   7   5 4
```

**三个关键词**：

| 概念 | 含义 |
|------|------|
| **完全二叉树** | 除最后一层外填满；最后一层从左到右填，不能有空洞 |
| **堆序性质** | 父节点与孩子之间的大小关系（小根堆：父 ≤ 子；大根堆：父 ≥ 子） |
| **堆顶** | 根节点，O(1) 获取当前最小/最大值 |

**堆不是什么**：

| 对比 | 堆 | 说明 |
|------|-----|------|
| vs **二叉搜索树 BST** | 堆只保证「父与孩子」的大小关系，**不保证**左子 < 父 < 右子 | BST 中序遍历有序；堆不能 |
| vs **排序数组** | 堆只能 O(1) 取最值，**不能** O(1) 查任意第 K 大 | 取完最值要 O(log n) 调整 |
| vs **普通队列** | 堆是 **按优先级** 出队，不是 FIFO | 也叫 **优先队列** |

**一句话**：堆 = 用完全二叉树组织、能快速拿「当前最小/最大」的动态集合。

---

### 5.2 堆的核心性质

堆有两类性质，**缺一不可**：

#### 性质 1：结构性质（Shape Property）

- 是一棵 **完全二叉树**
- 用数组存储时，若长度为 n，则树高为 ⌊log₂n⌋ + 1
- **最后一层可以不满，但一定从左到右连续**

```
✅ 完全二叉树          ❌ 不是完全二叉树（最后一层有空洞）
      A                      A
    /   \                  /   \
   B     C                B     C
  / \                    /       \
 D   E                  D         E
```

#### 性质 2：堆序性质（Heap-Order Property）

**小根堆（Min-Heap）**：任意节点 ≤ 其所有孩子（父 ≤ 子）

**大根堆（Max-Heap）**：任意节点 ≥ 其所有孩子（父 ≥ 子）

```
小根堆示例：[1, 3, 2, 7, 5, 4]        大根堆示例：[7, 5, 4, 3, 2, 1]
        1                                    7
      /   \                                /   \
     3     2                              5     4
    / \   /                              / \   /
   7   5 4                              3   2 1
```

**重要推论**（面试常考）：

1. **堆顶是全局最小（小根堆）或全局最大（大根堆）**——O(1) 获取
2. **堆没有整体有序**：上面例子里 3 和 2 谁大谁小不确定，7 比 3 大但 7 在底层
3. **不能二分查找**：只知道「父比子小/大」，不知道左子树与右子树的关系
4. **任意子树也是堆**：以任意节点为根的子树仍满足堆序

---

### 5.3 小根堆 vs 大根堆

| | **小根堆（Min-Heap）** | **大根堆（Max-Heap）** |
|---|------------------------|------------------------|
| 堆顶 | **全局最小值** | **全局最大值** |
| 父子关系 | 父 ≤ 子 | 父 ≥ 子 |
| `peek()` / 堆顶 | 最小 | 最大 |
| Python `heapq` | 默认就是小根堆 | 元素取负：`heappush(h, -x)` |
| 典型用途 | 取最小、K 路归并、Dijkstra | 取最大、Top K **最小** 守门 |

**同一组数据，两种堆顶不同**：

```
数据：3, 1, 4, 1, 5, 9, 2, 6

小根堆堆顶 → 1（全局最小）
大根堆堆顶 → 9（全局最大）

数组都不保证有序，只是堆顶保证最值。
```

**怎么选？**

```
需要反复取「当前最小」→ 小根堆
需要反复取「当前最大」→ 大根堆
Top K 最大（保留 k 个候选）→ size=k 小根堆守门 → 见 §5.9
Top K 最小（保留 k 个候选）→ size=k 大根堆守门
```

---

### 5.4 堆 vs 优先队列 vs 排序

这三个概念经常混用：

| | **堆** | **优先队列（Priority Queue）** | **排序** |
|---|--------|----------------------------------|----------|
| 本质 | 一种 **数据结构** | 一种 **抽象数据类型 ADT** | 一种 **操作/算法** |
| 关系 | 堆是优先队列的 **常见实现** | 「按优先级出队」，不限定底层 | 整体有序 |
| 取最值 | O(1) peek + O(log n) pop | 同左 | O(1) 取首尾（已排好） |
| 插入 | O(log n) | O(log n) | O(n) 插入排序；O(log n) 二分+移动 |
| 是否整体有序 | ❌ | ❌ | ✅ |
| 典型场景 | Top K、Dijkstra、定时器 | 任务调度、事件模拟 | 需要全序输出 |

```
优先队列（接口）          堆（实现）
┌─────────────────┐      ┌─────────────────┐
│ push(priority)  │ ──→  │ 完全二叉树+堆序  │
│ pop() → 最高优先 │      │ 数组存储         │
└─────────────────┘      └─────────────────┘
                           也可用：二叉搜索树、配对堆…
                           面试/刷题默认指二叉堆
```

**和排序算法里的「堆排序」**：堆排序利用堆的性质，反复 pop 堆顶得到升序/降序，O(n log n)，但 **不稳定、常数大**，工程上不如快排常用（见面试 Q7）。

### 5.5 数组存储与下标

堆在工程实现里 **几乎都用数组**，不用指针链表。

#### 为什么用完全二叉树 + 数组？

**完全二叉树性质**：可以用数组紧凑存储，无浪费

```
      1              下标:  1   2   3   4   5   6
    /   \            值:   [_, 1, 2, 3, 4, 5, 6]  （索引 0 不用或作哨兵）
   2     3
  / \   /
 4   5 6
```

#### 下标公式（0-indexed，面试两种写法都要会）

**1-indexed**（上文树图、许多教材）：

```
父节点：i / 2
左孩子：2 * i
右孩子：2 * i + 1
```

**0-indexed**（Python `heapq`、LeetCode 常用）：

```
父节点：(i - 1) // 2
左孩子：2 * i + 1
右孩子：2 * i + 2
```

#### 为什么不用指针？

- **缓存友好**：连续内存，CPU 预取命中高
- **节省空间**：无 left/right 指针
- **计算快**：父子下标 O(1) 算术，可位运算 `i<<1`, `i>>1`（1-indexed）

### 5.6 基本操作与复杂度

| 操作 | 做什么 | 时间 | 说明 |
|------|--------|------|------|
| **peek / top** | 看堆顶，不删 | O(1) | 堆顶在 `heap[0]`（0-indexed） |
| **push / insert** | 插入元素 | O(log n) | 放到末尾 → 向上调整（sift up） |
| **pop** | 弹出堆顶（最值） | O(log n) | 末尾换到根 → 向下调整（sift down） |
| **heapify / buildHeap** | 无序数组建堆 | O(n) | 自底向上下沉，不是 n 次 push |
| **heapify one** | 修改某元素后恢复堆序 | O(log n) | sift up 或 sift down 之一 |

**push 和 pop 的流程（小根堆）**：

```
push(0) 到 [3, 5, 7]:
  1. 追加到末尾 → [3, 5, 7, 0]
  2. 0 上浮：0↔5 → 0↔3 → [0, 3, 7, 5]

pop():
  1. 保存堆顶 0
  2. 末尾 5 换到根 → [5, 3, 7]
  3. 5 下沉：5↔3 → [3, 5, 7]
  4. 返回 0
```

**建堆 O(n) 而非 O(n log n)**：从最后一个非叶节点开始向下调整，均摊分析每个节点下沉次数有限。

### 5.7 堆化过程（Heapify）

#### 向上调整（Sift Up / Bubble Up）

插入新元素后，与父节点比较并交换，直到满足堆序或到根。

```python
def bubble_up(heap, i):
    """
    插入新元素后，向上调整
    时间复杂度：O(logn)
    """
    while i > 1:  # 不是根节点（1-indexed）
        parent = i // 2
        if heap[i] < heap[parent]:  # 小根堆
            heap[i], heap[parent] = heap[parent], heap[i]
            i = parent
        else:
            break
```

#### 向下调整（Sift Down / Bubble Down）

删除堆顶后，把末尾元素放到根，与孩子比较并交换，直到满足堆序或到叶子。

```python
def bubble_down(heap, i, size):
    """
    删除根节点后，向下调整
    时间复杂度：O(logn)
    """
    while 2 * i <= size:  # 有左孩子（1-indexed）
        smallest = 2 * i
        if 2 * i + 1 <= size and heap[2*i+1] < heap[smallest]:
            smallest = 2 * i + 1
        
        if heap[i] > heap[smallest]:
            heap[i], heap[smallest] = heap[smallest], heap[i]
            i = smallest
        else:
            break
```

### 5.8 手写堆

```python
class MinHeap:
    """
    小根堆实现
    """
    def __init__(self):
        self.heap = [None]  # 索引0不用
        self.size = 0
    
    def push(self, val):
        """
        插入：O(logn)
        1. 放到数组末尾
        2. 向上调整
        """
        self.heap.append(val)
        self.size += 1
        self._bubble_up(self.size)
    
    def pop(self):
        """
        删除最小值：O(logn)
        1. 用最后一个元素替换根
        2. 向下调整
        """
        if self.size == 0:
            raise Exception("Heap is empty")
        
        min_val = self.heap[1]
        self.heap[1] = self.heap[self.size]
        self.heap.pop()
        self.size -= 1
        
        if self.size > 0:
            self._bubble_down(1)
        
        return min_val
    
    def peek(self):
        """查看最小值：O(1)"""
        if self.size == 0:
            raise Exception("Heap is empty")
        return self.heap[1]
    
    def _bubble_up(self, i):
        while i > 1:
            parent = i // 2
            if self.heap[i] < self.heap[parent]:
                self.heap[i], self.heap[parent] = self.heap[parent], self.heap[i]
                i = parent
            else:
                break
    
    def _bubble_down(self, i):
        while 2 * i <= self.size:
            smallest = 2 * i
            if 2*i+1 <= self.size and self.heap[2*i+1] < self.heap[smallest]:
                smallest = 2 * i + 1
            
            if self.heap[i] > self.heap[smallest]:
                self.heap[i], self.heap[smallest] = self.heap[smallest], self.heap[i]
                i = smallest
            else:
                break
```

### 5.9 经典应用

#### 应用1：Top K 问题 ⭐⭐⭐

> **LeetCode 刷题入口**：见 [03-LeetCode分类刷题指南 §11 堆/优先队列](./03-LeetCode分类刷题指南.md#11-堆优先队列-)

这是堆相关题 **最反直觉** 的点：找「最大的 K 个」反而常用 **小根堆**；找「最小的 K 个」反而常用 **大根堆**。

##### 核心直觉：堆是「守门员」，不是「排行榜」

```
❌ 错误直觉：找 Top K 最大 → 用大根堆，堆顶就是答案
✅ 正确直觉：维护 size=k 的堆当「门槛」，堆顶是守门员
```

你要的不是「随时看到全局最大值」，而是 **只保留 K 个候选，踢掉不该进的**。

**小根堆（size=k）守门——找 Top K 大：**

```
堆顶 = 当前 K 个候选里最小的 = 「第 K 名的门槛线」

新元素来了：
  ≤ 堆顶 → 不可能进 Top K，丢弃
  > 堆顶 → Pop 堆顶（踢掉垫底的），Push 新元素
```

堆里始终是「目前见过的最高的 k 个」。

##### 一句话决策表

| 目标 | 堆的大小 | 堆的类型 | 堆顶含义 |
|------|----------|----------|----------|
| Top K **最大** | k | **小根堆** | 第 K 大的门槛，小的被踢 |
| Top K **最小** | k | **大根堆** | 第 K 小的门槛，大的被踢 |
| 全局最大 / 最小 | 1 或 n | 大根堆 / 小根堆 | 直接取堆顶 |
| 第 K 大（单个数） | k | **小根堆** | 扫完后堆顶即答案 |
| 第 K 小（单个数） | k | **大根堆** | 扫完后堆顶即答案 |

**对称记忆**：

```
找大的 Top K → 小根堆守门（堆顶是 K 个里最小的）
找小的 Top K → 大根堆守门（堆顶是 K 个里最大的）
```

##### 手推：LC347 `nums = [1,1,1,2,2,3]`, `k = 2`

统计频次：`1→3, 2→2, 3→1`。要找频次最高的 2 个。

**小根堆（按频次），size=2：**

```
处理 (1,3): 堆=[(1,3)]                         size=1
处理 (2,2): 堆=[(2,2),(1,3)]                   size=2，堆顶频次=2
处理 (3,1): Push → 超 k → Pop 堆顶 (3,1)
            最终=[(2,2),(1,3)]                   ✅
```

Pop 掉的是 **K 个候选里频次最低的**，不是全局垃圾。

**写法 A：size=k 小根堆（通用，k << n）**

```python
def top_k_frequent(nums, k):
    count = {}
    for num in nums:
        count[num] = count.get(num, 0) + 1

    heap = []
    for num, cnt in count.items():
        heapq.heappush(heap, (cnt, num))
        if len(heap) > k:
            heapq.heappop(heap)  # 踢掉频次最低的
    return [num for _, num in heap]
# O(n log k) 时间，O(k) 空间
```

##### 经典题型对照

| 题目 | 目标 | 用法 |
|------|------|------|
| LC347 前 K 个高频元素 | 频次 Top K | size=k **小根堆**（按频次） |
| LC215 数组中第 K 大元素 | 第 K 大 | size=k **小根堆**，堆顶即答案 |
| LC703 数据流第 K 大 | 动态第 K 大 | 同上，流式 Push + 超 k 就 Pop |
| LC973 最接近原点的 K 个点 | 距离最小的 K 个 | size=k **大根堆**（踢距离大的） |
| LC295 数据流中位数 | 中位数 | 大根堆 + 小根堆各管一半 |
| LC23 合并 K 个有序链表 | K 路归并 | size=k **小根堆** |
| LC378 有序矩阵第 K 小 | 第 K 小 | **小根堆** + 多路扩展 |

##### 为什么反直觉？

1. 「Top K 最大」和「大根堆」字面相似，但大根堆堆顶是 **全局最大**，不是 **第 K 名门槛**
2. 小根堆 Pop 最小值，像是在「扔差的」，实际扔的是 **Top K 集合里垫底的**
3. 堆在这里是 **动态过滤器**，不是排序输出

##### 海量数据 Top K（工程扩展）

**场景**：10 亿个数中找最大的 1000 个

| 方案 | 时间 | 空间 | 适用 |
|------|------|------|------|
| 全量排序 | O(n log n) | O(n) | ❌ 内存不够 |
| size=k 小根堆 | O(n log k) | O(k) | ✅ 单机流式 |
| 快速选择 | O(n) 均摊 | O(1) | ✅ 只要第 K 个值 |
| 分治 + 局部 Top K | O(n log k) | O(k) | ✅ 分布式 MapReduce |

```python
def top_k_largest(nums, k):
    heap = []
    for num in nums:
        if len(heap) < k:
            heapq.heappush(heap, num)
        elif num > heap[0]:
            heapq.heapreplace(heap, num)
    return heap
```

分布式：每台机器局部 Top K → 汇总后再 Top K 一次。

#### 应用2：Go time 包的四叉堆⭐⭐⭐

**Go runtime的定时器管理**：每个P（processor）有一个定时器堆

**为什么用四叉堆而不是二叉堆？**

```go
// Go源码：runtime/time.go
// 四叉堆定义
type timer struct {
    when   int64  // 触发时间（key）
    period int64
    f      func(interface{}, uintptr)  // 回调函数
    arg    interface{}
}

// 四叉堆父子关系
func parent(i int) int {
    return (i - 1) / 4  // 父节点
}

func child(i int) int {
    return 4*i + 1  // 第一个孩子
}
```

**二叉堆 vs 四叉堆**：

| 操作 | 二叉堆 | 四叉堆 |
|------|--------|--------|
| **插入** | O(log₂n) | O(log₄n) = O(log₂n / 2) |
| **删除** | O(log₂n) | O(log₄n) |
| **比较次数** | 每层1次 | 每层3次（4个孩子选最小） |

**为什么Go选择四叉堆？**

1. **缓存友好**：
   ```
   二叉堆：父+2个孩子 = 3个节点
   四叉堆：父+4个孩子 = 5个节点
   
   CPU缓存行：64字节
   - timer结构：约40字节
   - 四叉堆一次可能加载父+4个孩子到缓存
   - 二叉堆需要多次缓存加载
   ```

2. **插入更快**：
   ```
   Go的定时器场景：频繁插入（创建timer），较少删除
   四叉堆插入更少层数：log₄(n) < log₂(n)
   ```

3. **实测性能更好**：
   - 二叉堆：深度大，缓存miss多
   - 四叉堆：深度小，虽然每层比较多，但总体更快

**完整实现**：

```go
// 四叉堆操作（Go runtime简化版）
func siftUp(heap []timer, i int) {
    when := heap[i].when
    tmp := heap[i]
    
    for i > 0 {
        p := (i - 1) / 4  // 父节点
        if when >= heap[p].when {
            break
        }
        heap[i] = heap[p]
        i = p
    }
    heap[i] = tmp
}

func siftDown(heap []timer, i int, n int) {
    when := heap[i].when
    tmp := heap[i]
    
    for {
        c := 4*i + 1  // 第一个孩子
        if c >= n {
            break
        }
        
        // 在4个孩子中找最小的
        w := heap[c].when
        minChild := c
        for j := c + 1; j < c+4 && j < n; j++ {
            if heap[j].when < w {
                w = heap[j].when
                minChild = j
            }
        }
        
        if w >= when {
            break
        }
        
        heap[i] = heap[minChild]
        i = minChild
    }
    heap[i] = tmp
}
```

**Go定时器优化历史**：
- **Go 1.10之前**：全局定时器堆 + 全局锁（性能瓶颈）
- **Go 1.10-1.13**：每个P一个定时器堆（减少锁竞争）
- **Go 1.14+**：网络轮询器集成，进一步优化

#### 应用3：Dijkstra最短路径算法

```python
def dijkstra(graph, start):
    """
    Dijkstra算法：单源最短路径
    
    使用堆优化：
    - 朴素版：O(n²)
    - 堆优化版：O((V+E)logV)
    """
    import heapq
    
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    
    heap = [(0, start)]  # (距离, 节点)
    visited = set()
    
    while heap:
        d, u = heapq.heappop(heap)
        
        if u in visited:
            continue
        visited.add(u)
        
        for v, weight in graph[u]:
            if dist[u] + weight < dist[v]:
                dist[v] = dist[u] + weight
                heapq.heappush(heap, (dist[v], v))
    
    return dist
```

**为什么用堆？**
- 每次需要取距离最小的节点
- 堆可以O(logn)取最小值
- 朴素版需要O(n)遍历找最小值

### 6.2 图的遍历

#### 6.2.1 DFS vs BFS 选型

| 场景 | 推荐 | 原因 |
|------|------|------|
| **最短路径（无权图）** | BFS | 按层扩展，第一次到达 = 最短步数 |
| **连通分量 / 沉岛** | DFS 或 BFS | 均可 |
| **拓扑排序** | DFS 后序 或 Kahn BFS | 见 §6.3 |
| **路径存在性** | DFS | 栈深 O(h)，常更省空间 |
| **求所有路径 / 所有方案** | 回溯 DFS | 要撤销，**不能**用 BFS visited 一把梭 |

#### 6.2.2 模板（Go + Python）

```go
func bfs(graph [][]int, start int) {
    visited := map[int]bool{start: true}
    queue := []int{start}

    for len(queue) > 0 {
        node := queue[0]
        queue = queue[1:]
        // 处理 node

            if !visited[neighbor] {
                visited[neighbor] = true

}
```

#### 6.2.3 BFS 的 visited：为什么不需要回溯

这是 BFS 与回溯最容易混淆的点。

**常见疑问**：节点 `X` 会被多条路径到达，`visited` 挡掉后来的路，会不会像**贪心**一样错过全局最优？

**结论：在无权最短路问题里不会。** BFS 不是「每步做局部最优选择」，而是**按距离一层层扩展**：

```
第 0 层：起点
第 1 层：距起点恰好 1 步的所有节点
第 2 层：距起点恰好 2 步的所有节点
...
```

**核心性质**：节点 `X` **第一次**被访问时，所用步数就是 `start → X` 的最短路长度。之后任何路径再到 `X`，步数 **≥** 该长度，可以直接跳过。

| | BFS + visited | 回溯 DFS |
|--|---------------|----------|
| 目标 | 最短步数 / 最少操作 | 所有解、所有排列 |
| 同一状态 | 只处理一次（第一次最优） | 可能多次访问，需撤销 |
| visited 后 | **不撤销** | path/used **必须撤销** |
| 像贪心吗 | ❌ 有最短路定理保证 | ❌ 是穷举，不是贪心 |

**被挡掉的路径不是「可能更优的未知路」，而是「已证明 ≥ 当前最短步数的路」。**

**最优子结构**（无权图）：`dist(start, end) = dist(start, X) + dist(X, end)`。从 `X` 继续 BFS 的最优性，与「从哪条同长度路径走到 X」无关；因此同距离重复到达 `X` 也无需再扩展。

**什么时候「一次 visited」不够？**

| 场景 | 原因 | 做法 |
|------|------|------|
| 边权不同 | 后到的路径可能更短 | Dijkstra，按距离 relax |
| 状态含额外维度 | 同一节点不同状态 | `visited[node][state]` |
| 求所有路径 | 不是最短路 | 回溯，不用 BFS 剪枝 |

#### 6.2.4 隐式图 BFS：LC433 最小基因变化

基因串 = 节点；差 1 个碱基且在 `bank` 中 = 边。每次突变代价为 1 → BFS 求最短路。

```go
func minMutation(startGene, endGene string, bank []string) int {
    set := make(map[string]struct{}, len(bank))
    for _, g := range bank {
        set[g] = struct{}{}
    }
    if _, ok := set[endGene]; !ok {
        return -1
    }

    genes := []byte{'A', 'C', 'G', 'T'}
    visited := map[string]bool{startGene: true}
    queue := []string{startGene}
    step := 0

    for len(queue) > 0 {
        size := len(queue)
        for i := 0; i < size; i++ {
            cur := queue[0]
            queue = queue[1:]
            if cur == endGene {
                return step
            }
            b := []byte(cur)
            for j := 0; j < 8; j++ {
                orig := b[j]
                for _, g := range genes {
                    if g == orig {
                        continue
                    }
                    b[j] = g
                    next := string(b)
                    if _, ok := set[next]; !ok || visited[next] {
                        b[j] = orig
                        continue
                    }
                    visited[next] = true
                    queue = append(queue, next)
                    b[j] = orig
                }
            }
        }
        step++
    }
    return -1
}
```

```python
from collections import deque

def minMutation(start, end, bank):
    bank_set = set(bank)
    if end not in bank_set:
        return -1
    genes = "ACGT"
    visited = {start}
    queue = deque([(start, 0)])
    while queue:
        cur, step = queue.popleft()
        if cur == end:
            return step
        lst = list(cur)
        for j in range(8):
            orig = lst[j]
            for g in genes:
                if g == orig:
                    continue
                lst[j] = g
                nxt = "".join(lst)
                if nxt in bank_set and nxt not in visited:
                    visited.add(nxt)
                    queue.append((nxt, step + 1))
                lst[j] = orig
    return -1
```

### 6.3 工程应用：微服务依赖检测

**问题**：检测微服务之间是否有循环依赖

```python
def has_cycle(graph):
    """
    拓扑排序检测环
    
    Kahn算法：
    1. 找入度为0的节点
    2. 删除该节点及其出边
    3. 重复，直到无入度为0的节点
    4. 如果还有剩余节点，说明有环
    """
    from collections import deque, defaultdict
    
    # 计算入度
    in_degree = defaultdict(int)
    for u in graph:
        for v in graph[u]:
            in_degree[v] += 1
    
    # 找入度为0的节点
    queue = deque([u for u in graph if in_degree[u] == 0])
    count = 0
    
    while queue:
        u = queue.popleft()
        count += 1
        
        for v in graph[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0:
                queue.append(v)
    
    return count != len(graph)  # 有剩余节点 = 有环
```

## 7. 排序算法

### 7.1 快速排序原理

#### Partition过程

```python
def partition(arr, left, right):
    """
    分区：选pivot，小于pivot的放左边，大于的放右边
    
    返回：pivot的最终位置
    """
    pivot = arr[right]  # 选最后一个元素为pivot
    i = left - 1  # i指向小于pivot的区域的最后一个元素
    
    for j in range(left, right):
        if arr[j] < pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    
    # 将pivot放到正确位置
    arr[i + 1], arr[right] = arr[right], arr[i + 1]
    return i + 1

def quicksort(arr, left, right):
    """
    快速排序：O(nlogn)平均，O(n²)最坏
    """
    if left < right:
        pi = partition(arr, left, right)
        quicksort(arr, left, pi - 1)
        quicksort(arr, pi + 1, right)
```

**为什么快排快？**
- **原地排序**：不需要额外空间
- **缓存友好**：顺序访问内存
- **常数较小**：相比归并排序

**为什么最坏O(n²)？**
- 每次pivot都是最小/最大值
- 退化成选择排序

**如何避免？**
- 随机选pivot
- 三数取中（首、中、尾）

### 7.2 归并排序原理

```python
def merge_sort(arr):
    """
    归并排序：O(nlogn)，稳定排序
    """
    if len(arr) <= 1:
        return arr
    
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    
    return merge(left, right)

def merge(left, right):
    """合并两个有序数组"""
    result = []
    i = j = 0
    
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # ≤保证稳定性
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

**为什么归并是稳定排序？**
- 相等元素，优先取左边 → 保持相对顺序

**为什么工程中少用归并？**
- 需要O(n)额外空间
- 快排原地排序，更节省内存

## 8. 动态规划

### 8.1 动态规划原理

#### 什么时候用DP？

**两个条件**：
1. **最优子结构**：大问题的最优解包含小问题的最优解
2. **重叠子问题**：递归过程中，子问题重复出现

#### 经典例子：斐波那契数列

**方法1**：朴素递归（❌ 指数复杂度）

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)

# 时间复杂度：O(2ⁿ)
# fib(5)会计算fib(3)两次
```

**方法2**：记忆化搜索（✅ O(n)）

```python
def fib(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n-1, memo) + fib(n-2, memo)
    return memo[n]

# 时间复杂度：O(n)
# 每个子问题只计算一次
```

**方法3**：动态规划（✅ O(n)，空间优化）

```python
def fib(n):
    if n <= 1:
        return n
    
    # 只需保存前两个状态
    prev2, prev1 = 0, 1
    for i in range(2, n + 1):
        curr = prev1 + prev2
        prev2, prev1 = prev1, curr
    
    return prev1

# 时间：O(n)，空间：O(1)
```

### 8.2 背包问题

#### 0-1背包

```python
def knapsack_01(weights, values, capacity):
    """
    0-1背包：每个物品只能选一次
    
    状态定义：dp[i][w] = 前i个物品，容量w的最大价值
    状态转移：
    - 不选第i个：dp[i][w] = dp[i-1][w]
    - 选第i个：dp[i][w] = dp[i-1][w-weights[i]] + values[i]
    取最大值
    """
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        for w in range(capacity + 1):
            # 不选第i个物品
            dp[i][w] = dp[i-1][w]
            
            # 选第i个物品（如果放得下）
            if w >= weights[i-1]:
                dp[i][w] = max(dp[i][w], 
                              dp[i-1][w - weights[i-1]] + values[i-1])
    
    return dp[n][capacity]
```

**空间优化**：

```python
def knapsack_01_optimized(weights, values, capacity):
    """
    空间优化：O(capacity)
    
    关键：从右往左更新（避免覆盖）
    """
    dp = [0] * (capacity + 1)
    
    for i in range(len(weights)):
        # ⭐ 从右往左，避免dp[w-weights[i]]被提前更新
        for w in range(capacity, weights[i] - 1, -1):
            dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    
    return dp[capacity]
```

**为什么从右往左？**
```
从左往右：dp[w-weights[i]]可能已经更新（相当于选了两次物品）
从右往左：dp[w-weights[i]]还是上一行的值（正确）
```

### 8.3 工程应用：Redis内存淘汰算法

**LRU-K算法**：动态规划思想

```python
class LRU_K:
    """
    LRU-K：记录最近K次访问时间
    
    淘汰策略：淘汰第K次访问时间最早的
    
    为什么？
    - LRU（K=1）：一次访问就进缓存，容易被扫描污染
    - LRU-2：需要访问2次才稳定，抗污染
    """
    def __init__(self, capacity, k=2):
        self.capacity = capacity
        self.k = k
        self.cache = {}
        self.history = {}  # key → [访问时间列表]
        self.time = 0
    
    def get(self, key):
        self.time += 1
        
        if key in self.cache:
            # 记录访问时间
            if key not in self.history:
                self.history[key] = []
            self.history[key].append(self.time)
            
            # 只保留最近K次
            if len(self.history[key]) > self.k:
                self.history[key].pop(0)
            
            return self.cache[key]
        
        return -1
    
    def put(self, key, value):
        self.time += 1
        
        if len(self.cache) >= self.capacity:
            # 淘汰：找第K次访问时间最早的
            victim = min(self.history, 
                        key=lambda k: self.history[k][self.k-1] 
                                      if len(self.history[k]) >= self.k 
                                      else 0)
            del self.cache[victim]
            del self.history[victim]
        
        self.cache[key] = value
        if key not in self.history:
            self.history[key] = []
        self.history[key].append(self.time)
```

## 9. 回溯算法

> **与 BFS 的分工**：回溯求**所有解**（排列/组合/子集/N 皇后），要撤销选择；BFS 求**无权最短路**，`visited` 不撤销。见 [§6.2.3](#623-bfs-的-visited为什么不需要回溯)。

### 9.1 回溯算法模板

**核心思想**：在决策树上 DFS，穷举 + 剪枝；**必须撤销**上次选择。

**Go 模板**

```go
var result [][]int

func backtrack(path []int /* 其他参数 */) {
    if isEnd(path) {
        tmp := make([]int, len(path))
        copy(tmp, path)
        result = append(result, tmp)
        return
    }
    for _, choice := range choices {
        if !isValid(choice) {
            continue
        }
        path = append(path, choice)
        backtrack(path /* ... */)
        path = path[:len(path)-1] // 撤销
    }
}
```

**Python 模板**

```python
def backtrack(path, choices):
    if is_end(path):
        result.append(path[:])  # 快照
        return
    for choice in choices:
        if not is_valid(choice):
            continue
        path.append(choice)
        backtrack(path, next_choices(choices))
        path.pop()  # 撤销
```

**回溯 vs 其他范式**

| | 回溯 | BFS 最短路 | 动态规划 |
|--|------|-----------|---------|
| 求什么 | 所有解 / 一种可行解 | 最少步数 | 最优值 / 方案数 |

### 9.2 子集 / 组合 / 排列：统一框架

同一套 DFS：**做选择 → 递归 → 撤销**。差别在「下一层能选什么」和「何时收集答案」。

| 题型 | 顺序重要？ | 下一层选择 | 何时收集 | 代表题 |
|------|-----------|-----------|---------|--------|
| **子集** | 否 | `i+1`（start） | **每个节点** | LC78 |
| **组合** | 否 | `i+1` | `len(path)==k` | LC77 |
| **全排列** | 是 | `0..n-1` + `used` | `len(path)==n` | LC46/47 |
| **电话号** | 是（按位） | 映射表字母 | `idx==len` | LC17 |
| **N 皇后** | — | 每行试列 + 冲突检测 | 满 n 行 | LC51 |

**递进关系**

```
78 子集（每层收集，任意长度）
 └─ 77 组合（只在 len==k 收集，加剪枝）
46 全排列（used 替代 start，顺序重要）
 └─ 47 全排列 II（排序 + !used[i-1] 去重）
17 电话号（按 idx 分层，比 46 更简单）
51 N 皇后（按 row 分层 + 列/对角线约束）
```

### 9.3 收集答案：为什么要 copy

**铁律**：进入 `result` 的必须是**那一刻的快照**，不能是还会被回溯修改的 slice 引用。

```go
result = append(result, path)           // ✗ 共享底层数组，回溯后全乱
tmp := make([]int, len(path)); copy(tmp, path)
result = append(result, tmp)            // ✓
result = append(result, string(path))   // ✓ string 从 []byte 拷贝内容（LC17）
```

| 写法 | 是否安全 |
|------|---------|
| `append(result, path)`，path 会复用 | ✗ |
| `make + copy` 再 append | ✓ |
| `string(path)`（定长 `[]byte`） | ✓ 隐式拷贝内容 |
| 定长 `path[idx]=c` 不撤销 | ✓ 下一分支覆盖同位置 |

**易错（LC17）**：`path := make([]byte, n)` 时 `len(path)` 一开始就是 `n`，不能用 `len(path)==n` 当进度；要用 **`idx == n`** 表示填完所有位。

```python
def permute(nums):
    result = []
    def backtrack(path, used):
        if len(path) == len(nums):
            result.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            backtrack(path, used)
            path.pop()
            used[i] = False
    backtrack([], [False] * len(nums))
    return result
```

## 10. 贪心算法

### 10.1 贪心算法特点

- **局部最优**：每一步都做当前最优选择
- **全局最优**：希望局部最优能导致全局最优
- **不一定正确**：需要证明贪心策略的正确性

### 10.2 区间调度问题

**问题**：有N个活动，每个活动有开始时间和结束时间，求最多能参加几个活动

```python
def maxActivities(activities):
    """
    贪心策略：按结束时间排序，优先选择结束早的活动
    
    为什么贪心？
    - 结束越早，留给后续活动的时间越多
    - 局部最优 → 全局最优
    """
    # 按结束时间排序
    activities.sort(key=lambda x: x[1])
    
    count = 0
    last_end = 0
    
    for start, end in activities:
        # 如果当前活动的开始时间 >= 上一个活动的结束时间
        if start >= last_end:
            count += 1
            last_end = end
    
    return count

# 测试
activities = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
print(maxActivities(activities))  # 4: (1,4), (5,7), (8,11), (12,16)
```

### 10.3 跳跃游戏

**问题**：数组每个元素表示最大跳跃长度，判断能否到达最后一个位置

```python
def canJump(nums):
    """
    贪心策略：维护当前能到达的最远位置
    """
    max_reach = 0  # 当前能到达的最远位置
    
    for i in range(len(nums)):
        # 如果当前位置超过了最远可达位置，说明无法到达
        if i > max_reach:
            return False
        
        # 更新最远可达位置
        max_reach = max(max_reach, i + nums[i])
        
        # 如果已经能到达最后一个位置
        if max_reach >= len(nums) - 1:
            return True
    
    return True

# 测试

print(canJump([3, 2, 1, 0, 4]))  # False
```

### 12.1 前缀和

**用途**：快速计算区间和

```python
class NumArray:
    """
    问题：给定数组，多次查询区间[left, right]的和
    
    朴素方法：每次遍历O(n)
    前缀和：预处理O(n)，查询O(1)
    """
    def __init__(self, nums):
        # prefix[i] = nums[0] + nums[1] + ... + nums[i-1]
        self.prefix = [0]
        for num in nums:
            self.prefix.append(self.prefix[-1] + num)
    
    def sumRange(self, left, right):
        """
        sum(left, right) = prefix[right+1] - prefix[left]
        """
        return self.prefix[right + 1] - self.prefix[left]

# 测试
```

### 12.2 差分数组

**用途**：快速对区间进行加减操作

```python
class Difference:
    """
    问题：给定数组，多次对区间[left, right]的所有元素+val
    
    朴素方法：每次遍历O(n)
    差分数组：单次操作O(1)，最后还原O(n)
    """
    def __init__(self, nums):
        n = len(nums)
        # diff[i] = nums[i] - nums[i-1]
        self.diff = [0] * n
        self.diff[0] = nums[0]
        for i in range(1, n):
            self.diff[i] = nums[i] - nums[i - 1]
    
    def increment(self, left, right, val):
        """
        对[left, right]区间的所有元素+val
        """
        self.diff[left] += val
        if right + 1 < len(self.diff):
            self.diff[right + 1] -= val
    
    def result(self):
        """
        还原数组
        """
        n = len(self.diff)
        nums = [0] * n
        nums[0] = self.diff[0]
        for i in range(1, n):
            nums[i] = nums[i - 1] + self.diff[i]
        return nums

# 测试
diff = Difference([1, 2, 3, 4, 5])
diff.increment(1, 3, 2)  # [1,2,3,4,5] → [1,4,5,6,5]
print(diff.result())  # [1, 4, 5, 6, 5]
```

### 12.3 单调栈

**用途**：寻找下一个更大/更小元素

```python
def nextGreaterElement(nums):
    """
    问题：对于数组中的每个元素，找到右边第一个比它大的元素
    
    朴素方法：O(n^2)
    单调栈：O(n)
    """
    n = len(nums)
    result = [-1] * n
    stack = []  # 单调递减栈（存储索引）
    
    for i in range(n):
        # 当前元素 > 栈顶元素时，栈顶元素的答案就是当前元素
        while stack and nums[i] > nums[stack[-1]]:
            idx = stack.pop()
            result[idx] = nums[i]
        
        stack.append(i)
    
    return result
```

### 12.4 滑动窗口最大值

**问题**：给定数组和窗口大小k，求每个窗口的最大值

```python
from collections import deque

def maxSlidingWindow(nums, k):
    """
    单调队列：维护窗口内的单调递减序列
    """
    result = []
    dq = deque()  # 存储索引，保持单调递减
    
    for i in range(len(nums)):
        # 移除队首的过期元素（不在窗口内）
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        
        # 移除队尾比当前元素小的元素（它们不可能是最大值）
        while dq and nums[dq[-1]] < nums[i]:
            dq.pop()
        
        dq.append(i)
        
        # 窗口形成后，记录最大值（队首元素）
        if i >= k - 1:
            result.append(nums[dq[0]])
    
    return result

# 测试
```

### 12.5 二分查找专题

> 二分查找远不止"有序数组找目标值"，其核心思想是**通过判断条件缩小搜索空间**，适用于所有满足单调性/二段性的问题。

**二分查找的三种基本模板**：

```python
# 模板1：标准二分 - 查找精确值
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2  # 防溢出
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# 模板2：左边界二分 - 查找第一个 >= target 的位置
def lower_bound(nums, target):
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

# 模板3：右边界二分 - 查找最后一个 <= target 的位置
def upper_bound(nums, target):
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if nums[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo - 1
```

**高频应用场景**：

| 场景 | 核心思路 | 经典题目 |
|------|---------|---------|
| **旋转排序数组** | 先判断mid在左半段还是右半段 | LC33/LC81 |
| **峰值查找** | 比较mid与mid+1，向上坡方向移动 | LC162 |
| **二分答案（最小化最大值）** | 对答案空间二分 + 贪心验证 | LC410 分割数组 |
| **矩阵搜索** | 展开为一维或逐行二分 | LC74/LC240 |
| **求平方根/n次方** | 对结果空间 [0, x] 二分 | LC69 |

**关键易错点**：
- `lo + (hi - lo) // 2` 防止整数溢出
- `while lo <= hi` vs `while lo < hi`：取决于搜索空间是闭区间还是左闭右开
- 注意 `lo = mid + 1` 还是 `lo = mid`：错误选择导致死循环

### 12.6 字符串算法（KMP）

> KMP 算法通过预处理模式串的**最长公共前后缀（next数组/失配函数）**，实现 O(n+m) 的字符串匹配，避免暴力匹配中的回退。

**核心概念**：

- **next数组（前缀函数）**：`next[i]` = 模式串 `P[0..i]` 中最长的"既是前缀又是后缀"的长度
- **匹配过程**：文本指针永不回退，失配时只移动模式串指针到 `next[j-1]`

```python
def kmp_search(text, pattern):
    """KMP字符串匹配 - O(n+m)"""
    n, m = len(text), len(pattern)
    if m == 0:
        return 0
    
    # 构建next数组（前缀函数）
    next_arr = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and pattern[i] != pattern[j]:
            j = next_arr[j - 1]  # 回退到上一个最长前后缀
        if pattern[i] == pattern[j]:
            j += 1
        next_arr[i] = j
    
    # 匹配
    j = 0
    results = []
    for i in range(n):
        while j > 0 and text[i] != pattern[j]:
            j = next_arr[j - 1]
        if text[i] == pattern[j]:
            j += 1
        if j == m:
            results.append(i - m + 1)
            j = next_arr[j - 1]
    return results
```

**相关算法扩展（知识点提纲）**：
- **Rabin-Karp**：滚动哈希 O(n+m)，适合多模式匹配
- **Sunday算法**：工程实践中常比KMP更快（利用"坏字符"跳跃）
- **Aho-Corasick（AC自动机）**：多模式串匹配，基于Trie+失配指针，O(n+m+k)
- **后缀数组/后缀自动机**：高级字符串结构，用于最长公共子串、重复子串等

### 12.7 并查集（Union-Find）

> 并查集是解决**动态连通性问题**的高效数据结构，支持"合并集合"和"查询是否同一集合"两种操作，均摊近 O(1)。

**核心操作**：

```python
class UnionFind:
    """路径压缩 + 按秩合并，操作均摊 O(α(n)) ≈ O(1)"""
    
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.count = n  # 连通分量个数
    
    def find(self, x):
        """查找根节点（路径压缩）"""
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    
    def union(self, x, y):
        """合并两个集合（按秩合并）"""
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1
        self.count -= 1
        return True
    
    def connected(self, x, y):
        return self.find(x) == self.find(y)
```

**高频应用场景**：

| 场景 | 说明 | 经典题目 |
|------|------|---------|
| **图的连通分量** | 判断无向图中连通分量数 | LC547 省份数量 |
| **冗余连接** | 加边时若两端已连通则为冗余 | LC684 |
| **最小生成树（Kruskal）** | 按边权排序，逐边加入不成环即可 | LC1584 |
| **账户合并** | 邮箱归并到同一用户 | LC721 |
| **等式方程** | 相等关系 union，不等关系检查 | LC990 |

**优化要点**：
- **路径压缩**：find 时将所有节点直接连接到根（递归或迭代）
- **按秩合并**：小树挂大树，控制树高
- 两者结合使操作均摊 O(α(n))，α 为反阿克曼函数，实际可视为常数

### 12.8 字典树（Trie）

> Trie 是一种多叉树结构，用于高效存储和检索字符串集合，特别适用于**前缀匹配**场景。

**核心实现**：

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    """字典树 - 插入/查找/前缀查询均为 O(L)，L为字符串长度"""
    
    def __init__(self):
        self.root = TrieNode()
    
    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True
    
    def search(self, word):
        """精确查找"""
        node = self._find_node(word)
        return node is not None and node.is_end
    
    def starts_with(self, prefix):
        """前缀查找"""
        return self._find_node(prefix) is not None
    
    def _find_node(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node
```

**高频应用场景**：

| 场景 | 说明 | 经典题目 |
|------|------|---------|
| **自动补全** | 前缀匹配 + DFS收集所有后缀 | LC642 搜索自动补全 |
| **单词搜索II** | Trie + 回溯在矩阵中搜索 | LC212 |
| **词典中最长的单词** | 逐字符构建合法性检查 | LC720 |
| **异或最大值** | 按位建Trie，贪心选择 | LC421 |
| **回文对** | Trie存反转串，查找拼接回文 | LC336 |

**Trie 的工程扩展**：
- **压缩Trie（Radix Tree）**：将单链路径压缩为单节点，节省空间（Linux内核路由表使用）
- **双数组Trie（Double-Array Trie）**：用两个数组模拟Trie，空间极小、查找极快（中文分词 jieba/HanLP 使用）
- **AC自动机**：Trie + KMP思想的失配指针，用于多模式串同时匹配（敏感词过滤、病毒特征码检测）

### Q1: 两数之和

```python
def two_sum(nums, target):
    """
    时间：O(n)，空间：O(n)
    哈希表应用
    """
    seen = {}
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []
```

### Q2: 反转链表

```python
def reverse_list(head):
    """
    时间：O(n)，空间：O(1)
    """
    prev, curr = None, head
    while curr:
        next_node = curr.next
        curr.next = prev
        prev = curr
        curr = next_node
    return prev
```

### Q3: 二叉树最大深度

```python
def max_depth(root):
    """
    时间：O(n)，空间：O(h)
    """
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

### Q3.1: 递归里先写 `if root == nil` 是前序吗？LCA 为什么是后序？

**答案**：见 [§4.0 二叉树 DFS：前/中/后序如何区分](#40-二叉树-dfs前中后序如何区分)。简述：`if root == nil` 是递归终止条件，三种序都可以写在函数开头；**前/中/后序看「处理 root 的核心逻辑」相对 `dfs(left)`/`dfs(right)` 的位置**。最大深度、LCA 都要等左右子树返回值再算当前节点 → **后序**。前序是先处理 root 再往下（序列化、路径）；中序是左完再 root（BST 中序有序）。

### Q4: 快速排序的时间复杂度为什么是O(nlogn)？最坏情况是什么？

**答案**：
**平均O(nlogn)**：
- 每次partition将数组分成两半，需要递归logn层
- 每层需要O(n)比较，总共O(nlogn)

**最坏O(n²)**：
- 每次pivot都是最小/最大值（如有序数组、逆序数组）
- 分区退化成1和n-1，递归n层，每层O(n)

**如何优化**：
- 随机选择pivot
- 三数取中（首、中、尾的中间值）
- 小数组（<16）改用插入排序

### Q5: 为什么哈希表的查找是O(1)？什么情况下退化？

**答案**：
**O(1)原理**：
- 通过哈希函数将key映射到数组索引：`index = hash(key) % size`
- 直接通过索引访问，无需遍历

**退化情况**：
1. **哈希冲突严重**：所有key映射到同一bucket，链表长度为n，查找O(n)
2. **负载因子过高**：元素数量远超bucket数量，冲突概率增加

**工程解决**：
- Java HashMap：链表长度>8转红黑树，保证O(logn)
- 负载因子0.75时扩容
- Redis：渐进式rehash避免阻塞

### Q6: LRU缓存为什么用哈希表+双向链表？

**答案**：
**需求分析**：
- get(key)：O(1)查找 → 需要哈希表
- put时淘汰最久未使用：O(1)删除末尾 → 需要双向链表
- 访问后移动到头部：O(1)删除任意节点 → 双向链表（单向链表删除需O(n)找前驱）

**为什么不用其他结构**：
- 单向链表：删除节点需要O(n)
- 数组：删除中间元素需要O(n)移动
- 纯哈希表：无法记录访问顺序

### Q7: 堆是什么？有哪些核心性质？小根堆和大根堆有什么区别？

**答案**：见 [§5.1～5.3 堆基础](#51-堆是什么)。简述：

**堆** = 完全二叉树 + 堆序性质，用于 O(1) 取最值、O(log n) 插入删除。

**两类性质**：
1. **结构性质**：完全二叉树，最后一层从左到右连续
2. **堆序性质**：小根堆父 ≤ 子；大根堆父 ≥ 子

**与 BST 区别**：堆不保证左 < 父 < 右，**不能**中序遍历得有序序列；堆顶是全局最值，BST 需 O(log n) 找最值。

**小根堆 vs 大根堆**：
- 小根堆：堆顶 = 全局**最小**；Python `heapq` 默认
- 大根堆：堆顶 = 全局**最大**；Python 对元素取负模拟

**常见误区**：堆 **没有整体有序**，只有堆顶保证最值；Sibling 节点之间大小关系不确定。

### Q8: 堆排序为什么不如快速排序常用？

**答案**：
**理论上**：两者都是O(nlogn)

**实际差异**：
1. **缓存不友好**：堆排序访问模式跳跃（父子节点索引差距大），快排顺序访问
2. **常数因子大**：堆排序每次堆化需要多次比较（找最大孩子）
3. **不稳定**：堆排序不稳定，某些场景不适用

**堆的优势场景**：
- Top-K问题（只需要部分排序）
- 优先队列（频繁插入/删除最值）
- 外部排序（多路归并）

### Q9: 动态规划和贪心算法的区别？如何判断？

**答案**：
| 特性 | 动态规划 | 贪心算法 |
|------|---------|---------|
| **决策方式** | 考虑所有可能，取最优 | 每步只取当前最优 |
| **是否回溯** | 需要保存子问题结果 | 不需要 |
| **正确性** | 只要满足最优子结构 | 需要证明贪心选择性质 |
| **时间复杂度** | 通常更高 | 通常更低 |

**判断方法**：
- 能用贪心尽量用贪心（更简单高效）
- 贪心不正确时考虑DP
- 可以通过反例验证贪心是否正确

**典型例子**：
- 区间调度：贪心（按结束时间排序）
- 背包问题：DP（贪心不正确，如价值/重量最大不一定最优）

### Q10: 二分查找的边界条件为什么容易写错？如何记忆？

**答案**：
**三个易错点**：
1. `while lo <= hi` vs `while lo < hi`
2. `lo = mid + 1` vs `lo = mid`
3. `hi = mid - 1` vs `hi = mid`

**统一记忆法**：
```python
# 搜索区间 [lo, hi]（闭区间）
while lo <= hi:  # 区间非空时继续
    mid = lo + (hi - lo) // 2  # 防溢出
    if nums[mid] == target:
        return mid
    elif nums[mid] < target:
        lo = mid + 1  # [mid+1, hi]
    else:
        hi = mid - 1  # [lo, mid-1]
```

**不同变体的关键**：
- 找第一个>=target：`if nums[mid] >= target: hi = mid`，返回lo
- 找最后一个<=target：`if nums[mid] <= target: lo = mid`，返回hi

### Q11: 为什么MySQL用B+树而不是红黑树或哈希表？

**答案**：
**不用红黑树**：
- 红黑树高度log₂(n)，100万数据约20层，需要20次磁盘I/O
- B+树高度log_m(n)，m=1000时只需2-3层I/O

**不用哈希表**：
- 哈希表不支持范围查询（BETWEEN、>、<）
- 哈希表不支持排序
- 哈希表不支持前缀匹配（LIKE 'abc%'）

**B+树优势**：
- 高扇出降低树高，减少I/O
- 叶子节点链表支持范围查询
- 顺序I/O，利用磁盘预读

### Q12: 什么时候用递归？递归有什么问题？

**答案**：
**适用场景**：
- 问题有明确的递归结构（树、图遍历）
- 分治问题（归并排序、快排）
- 回溯问题（全排列、N皇后）

**潜在问题**：
1. **栈溢出**：递归深度过大（Linux默认栈8MB）
2. **重复计算**：如朴素斐波那契O(2ⁿ)
3. **空间开销**：每次调用占用栈空间

**优化方案**：
- 记忆化搜索解决重复计算
- 改用迭代（显式栈模拟）
- 尾递归优化（某些语言支持）

### Q13: 图的DFS和BFS分别适用什么场景？

**答案**：
| 场景 | 推荐算法 | 原因 |
|------|---------|------|
| **最短路径（无权图）** | BFS | 层次遍历保证最短 |
| **拓扑排序** | DFS | 后序遍历逆序即拓扑序 |
| **环检测** | DFS | 三色标记法 |
| **连通分量** | DFS/BFS | 都可以 |
| **迷宫最短路** | BFS | 层次扩展 |
| **路径存在性** | DFS | 空间更小 |

**空间复杂度**：
- DFS：O(h)，h为最大深度
- BFS：O(w)，w为最大宽度
- 树状结构：BFS空间可能更大

### Q13.1: BFS 的 visited 挡掉其他路径，会不会错过更优解？

**答案**：见 [§6.2.3 BFS 的 visited：为什么不需要回溯](#623-bfs-的-visited为什么不需要回溯)。简述：

- **不会**。无权图 BFS 按层扩展，**第一次到达节点的步数即最短**，后续路径步数 ≥ 该值。
- 被挡掉的不是「可能更优的未知路」，而是「已证明不更短的路」——与**贪心**不同，BFS 有最短路定理保证。
- **最优子结构**：从节点 `X` 到终点的最短距离，与「从哪条同长度路径到达 X」无关。
- **何时一次 visited 不够**：边权不同（Dijkstra）、状态含额外维度、求所有路径（改回溯）。

|------|------|------|------|------|--------|---------|
| **快速排序** | O(nlogn) | O(nlogn) | O(n²) | O(logn) | ❌ | 内存排序首选 |

### Q15: 如何判断一个问题能否用动态规划解决？

**答案**：
**两个必要条件**：

1. **最优子结构**：大问题的最优解包含子问题的最优解
   - 例：最短路径问题，A→C的最短路必经过中间节点B的最短路
   
2. **重叠子问题**：不同大问题会重复用到相同子问题
   - 例：斐波那契数列，fib(5)和fib(6)都需要fib(4)

**不满足最优子结构的反例**：
- 最长简单路径（不能重复经过节点）
- 子问题的最优解可能互相冲突

**DP三步走**：
1. 定义状态：dp[i]或dp[i][j]表示什么
2. 状态转移方程：dp[i]如何由dp[i-1]等推出
3. 初始条件和边界

### Q16: 如何处理海量数据的Top-K问题？

**答案**：见 [§5.4 应用1 Top K 问题](#应用1top-k-问题-) 完整版。简述：size=k **小根堆** O(n log k) O(k) 空间，适合单机流式；快速选择 O(n) 均摊只要第 K 个值；分布式则局部 Top K 再汇总。

```python
import heapq

def topK(nums, k):
    heap = []
    for num in nums:
        if len(heap) < k:
            heapq.heappush(heap, num)
        elif num > heap[0]:
            heapq.heapreplace(heap, num)
    return heap
```

### Q17: 单调栈解决什么问题？时间复杂度为什么是O(n)？

**答案**：
**适用问题**：
- 下一个更大/更小元素
- 柱状图中最大矩形
- 接雨水

**O(n)原理**：
- 每个元素最多入栈一次、出栈一次
- 总操作次数：2n = O(n)
- 虽然有while循环，但均摊每个元素只处理一次

**典型应用**：
```python
def nextGreater(nums):
    stack, res = [], [-1] * len(nums)
    for i, num in enumerate(nums):
        while stack and num > nums[stack[-1]]:
            res[stack.pop()] = num
        stack.append(i)
    return res
```

### Q18: 一致性哈希解决什么问题？

**答案**：
**问题**：分布式缓存节点变化时，普通哈希导致大量key迁移
```
普通哈希：hash(key) % n
节点从3变4：几乎所有key需要迁移
```

**一致性哈希**：
- 将哈希空间组织成环（0~2³²-1）
- 节点和key都映射到环上
- key存储在顺时针方向第一个节点

**优势**：
- 节点增减只影响相邻节点的key
- 迁移量从n减少到1/n

**虚拟节点**：
- 解决节点少时分布不均的问题
- 每个物理节点对应多个虚拟节点

### Q19: 红黑树和AVL树的区别？为什么实际中红黑树更常用？

**答案**：
| 特性 | AVL树 | 红黑树 |
|------|-------|--------|
| **平衡条件** | 高度差≤1（严格） | 最长路径≤2倍最短（近似） |
| **查找** | 更快（更平衡） | 略慢 |
| **插入/删除** | 更多旋转 | 更少旋转 |
| **适用场景** | 读多写少 | 读写均衡 |

**红黑树更常用的原因**：
1. 插入/删除操作更频繁时，红黑树旋转次数更少
2. 实现相对简单（AVL需要维护高度）
3. 综合性能更好（工业实践证明）

**应用**：
- 红黑树：Java HashMap、Linux CFS、C++ map
- AVL树：数据库索引（读多写少）

**参考思路**：

- 第二步：举例+画图（小规模例子手动模拟、找规律）
- 第三步：联想已知模式（排序/二分/双指针/滑窗/DFS/BFS/DP/贪心/单调栈）
- 第四步：先说暴力解（展示你能解出来），再分析瓶颈，逐步优化
- 第五步：编码前先和面试官确认思路、写代码时边写边说、写完跑测试用例
- 关键心态：不要沉默超过2分钟、卡住就和面试官沟通、展示思考过程比直接给出答案更重要

**D2：如何判断一道题应该用DP还是贪心？给出判断框架**

**参考思路**：
- 贪心特征：每步局部最优→全局最优（贪心选择性质）、不需要回头（无后效性）
- DP特征：最优子结构+重叠子问题、当前决策影响后续决策、需要记录状态
- 判断方法：先尝试贪心（能找到反例就不能贪心→转DP）、DP能做的贪心不一定能做
- 典型对比：活动选择（贪心✅）vs 01背包（贪心❌需DP）、跳跃游戏（贪心✅）vs 编辑距离（DP）
